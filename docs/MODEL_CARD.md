# Model card: RouteWise AI delay classifier

## Summary

| Item | Value |
|:--|:--|
| Task | Binary classification: will a shipment arrive late? |
| Prediction moment | At dispatch, before the shipment moves |
| Selected model | Logistic Regression (median imputation + standard scaling for numeric, mode imputation + one-hot for categorical) |
| Selection method | Stratified 5-fold CV on the training period, highest mean PR-AUC among 3 candidates |
| Decision threshold | 0.214, the max-F1 point on out-of-fold training predictions |
| Training data | 6,000 synthetic shipments (seed 42), dispatch dates in 2025 |
| Evaluation | Temporal holdout: last 25% by dispatch date (Oct 2 to Dec 31, 1,500 rows) |
| Owner | Muhammad Zubair, ZubairLabs |
| Status | Educational portfolio prototype. Not for operational decisions. |

## Intended use

Demonstrating how a delay-risk model should be built, evaluated and presented: dispatch-time features only, forward-in-time testing, calibration checks, and honest reporting. Suitable for learning, portfolio review and as a starting template.

**Not intended for:** real shipment decisions, carrier selection, customer ETA promises, or any claim about real logistics performance.

## Inputs

Eleven features, all available at dispatch: `distance_km`, `planned_days`, `weight_kg`, `weather_severity` (forecast), `traffic_index` (forecast), `warehouse_backlog`, `carrier_on_time_rate` (historical), `customs_clearance_required`, `transport_mode`, `region`, `priority`.

Excluded on purpose: `shipment_id`, `dispatch_date`, and the outcome columns `delayed`, `delay_days`, `actual_transit_days`, `customs_hold_hours`. The last one was a model input in the first version of this project; it was removed because a shipment's customs hold is only known after it reaches customs.

## Training data

Generated by `routewise.core.generate_data`. The label comes from a logistic formula over realised weather (forecast plus noise), traffic, backlog, carrier on-time rate, realised customs hold, distance, Sea mode and priority. `planned_days`, `weight_kg` and `region` have no effect in the formula. Delay rate: 20.3% overall, 23.3% in the holdout quarter (winter weather and peak-season backlog).

## Candidates (CV on 4,500 training-period rows)

| Model | PR-AUC | ROC-AUC | Brier |
|:--|--:|--:|--:|
| Logistic Regression | 0.495 | 0.793 | 0.126 |
| Random Forest, unweighted | 0.465 | 0.772 | 0.131 |
| Random Forest, class-balanced (original) | 0.456 | 0.774 | 0.167 |

The simulated relationship is close to linear in log-odds, so Logistic Regression fitting best is expected. The class-balanced forest inflates probabilities (worse Brier), which hurts both calibration and the meaning of the risk bands.

## Holdout results (1,500 unseen shipments)

| Metric | Value |
|:--|--:|
| ROC-AUC | 0.778 |
| PR-AUC | 0.531 (baseline 0.233) |
| Brier | 0.145 |
| At 0.50: precision / recall / F1 | 0.634 / 0.277 / 0.386 |
| At 0.214: precision / recall / F1 | 0.411 / 0.706 / 0.520 |

Calibration by band on never-in-sample scores: Low 8.6% predicted vs 9.1% observed; Medium 30.4% vs 30.6%; High 59.4% vs 59.1%.

Permutation importance (holdout PR-AUC drop): traffic 0.109, weather 0.101, carrier on-time 0.096, backlog 0.086, customs required 0.029, distance 0.023, mode 0.009, priority 0.006, others about 0.

## Checks

- Random 75/25 split: ROC-AUC 0.790, PR-AUC 0.494.
- Leaky variant with `customs_hold_hours`: ROC-AUC 0.793, PR-AUC 0.558. Shown in the app to make the cost of leakage visible.
- Automated tests assert that no outcome or ID column reaches the model, the holdout is strictly later than training, dashboard scores are never in-sample, and saved models reproduce predictions exactly.

## Limitations and risks

- All results are on simulated data and do not transfer to real operations.
- One temporal holdout only; no rolling back-tests or drift monitoring.
- Forecast features are idealised; real forecasts arrive late, change, and have gaps.
- Feature effects are associations inside the simulation, not causal effects.
- Risk band cut-offs (20% and 45%) and service weights are assumptions.
